# [#7][adapter] 복구 측 어댑터로 DB별 차이를 가둔다

> 선행: #6(복구)에서 나온 구체 구현을 추상화한다. [ADR-0003](<../adr/[ADR-0003] CDC 캡처 — 직접 구현 대신 Debezium Server 도입.md>), [ADR-0001](<../adr/[ADR-0001] 데이터 정합성 — 복제 시점이 아니라 복구 기준점으로.md>) 참고.

### 배경

ADR-0001은 저장소 종류마다 메커니즘이 다르다고 봤다. 그런데 **캡처 측(변경 읽기)은 ADR-0003의 Debezium 커넥터가 멀티 DBMS를 이미 해결**한다(MySQL·PostgreSQL·Oracle·SQL Server·MongoDB). 그래서 우리 어댑터가 가둘 것은 **복구/promote 측**과, Checkpoint가 읽는 **현재 offset**이다.

#6에서 온프레 MySQL용 복구 구현이 먼저 나온다. 이 이슈는 그걸 공통 인터페이스로 뽑아, 다음 DB의 복구를 파일 하나로 추가할 수 있게 만든다.

### 설계

**1. 어댑터 인터페이스는 두 가지다**

| 메서드 | 하는 일 |
| --- | --- |
| `현재 Offset 읽기` | 그 저장소가 지금 어디까지 왔는지 반환. 대개 Debezium offset store에서 읽는다. Checkpoint(#5)가 쓴다 |
| `기준점 C까지 맞춰 기동 (promote to C)` | 복제본을 C 지점까지 맞추고 그 위에서 가동. 복구(#6)가 쓴다 |

종류별 차이(MySQL은 Binlog로 C까지 채움, Managed DB는 Replica 승격 등)는 각 어댑터 내부에 캡슐화한다. 상위 로직은 이 두 메서드만 부른다.

**2. 새 DB = 캡처는 Debezium 설정, 복구는 어댑터 파일 하나**

- **캡처 측:** Debezium 커넥터 설정만 추가한다(#2 방식). 코드를 짜지 않는다.
- **복구 측:** 이 어댑터 파일 하나를 더한다. Checkpoint·복구·메타 로직은 고치지 않는다.

echo-was의 "새 환경 종류 = 파일 하나" 원칙과 같은 결이다.

**3. 온프레 MySQL 복구 어댑터를 첫 구현으로 뽑는다**

#6에서 만든 복구 구현을 이 인터페이스에 맞춰 정리한다. 이게 기준 구현(reference)이 되고, 이후 어댑터가 따를 계약이 된다.

### 작업

- 어댑터 인터페이스(`현재 Offset 읽기`·`기준점 C까지 맞춰 기동`) 정의.
- 온프레 MySQL 복구 어댑터를 인터페이스에 맞춰 추출.
- Checkpoint(#5)·복구(#6)가 구체 구현이 아니라 인터페이스를 통해 부르도록 배선.

### 완료 조건

- Checkpoint와 복구가 저장소 종류를 직접 알지 않고, 어댑터 인터페이스로만 호출한다.
- 온프레 MySQL 어댑터가 두 메서드를 구현하고, #6 복구가 이를 통해 동작한다.
- 새 DB의 복구를 추가할 때 상위 로직을 고치지 않아도 되는 구조다(계약이 문서로 있다).

### 이번에 하지 않는 것

- 캡처 측 어댑터. 캡처는 Debezium 커넥터가 맡는다(ADR-0003).
- Managed DB 복구 어댑터 실제 구현(provider-native, 별도 이슈).
- Object Storage 어댑터.
- 다중 저장소 Checkpoint 조율.
