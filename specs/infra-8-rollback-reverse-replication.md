## 1. 목표

컷오버(A→B) 후 **역방향 복제 B→A**로 A를 fallback으로 살려 두고, 장애가 나면 **60초 안에 A로 100% 복귀**한다(NFR-05). 수동 버튼과 Notion 절차서(Must), 오류율 문턱 자동 롤백(Should). 1차 기능 F9(롤백).

## 2. 현재 맥락과 확인된 사실

- 선행: #7에서 A→B 컷오버가 된다. 이 SPEC은 그 **되돌리기**다.
- 이전과 같은 메커니즘을 반대로 쓴다: 논리 복제 방향을 B→A로, 컷오버 절차(PgBouncer)를 A 방향으로.
- 회의(11/2): 복구 판단은 **헬스체크 API 폴링**으로 A가 돌아왔는지 보고 결정한다.
- 재난(갑자기 끊김)과 계획적 롤백을 구분한다. 재난 때는 A가 죽어 역방향 복제가 끊기므로, A 복구 후 재동기화가 선행된다.

## 3. 범위

### 포함

- 컷오버 직후 **역방향 복제 B→A** 세팅(평상시 A를 최신 가깝게 유지).
- **롤백 절차**(B→A): #7 컷오버의 역방향(PgBouncer PAUSE → 지연 0 → 시퀀스 맞춤 → A로 repoint → RESUME).
- **수동 롤백 버튼**(Must)과 **Notion 절차서**(Must).
- **헬스체크 폴링**으로 A 복구 판단.
- **오류율 문턱 자동 롤백**(Should).

### 제외

- 사용자 트래픽 전환·판정 규칙(#6). DB 롤백까지.
- 백업·PITR(#14).
- 재난 후 A를 처음부터 다시 세우는 인프라 재구축(Terraform `make up`, 인프라 파트).

## 4. 설계 (단계)

1. **역방향 복제 B→A** — A→B 컷오버가 끝나면 B를 publisher, A를 subscriber로 세운다. A가 살아 있는 한 B의 변경이 A로 흐른다.
2. **롤백 절차(B→A)** — #7과 같은 PgBouncer 컷오버를 방향만 바꿔 실행한다. 타임스탬프로 복귀 시간을 측정한다.
3. **수동 버튼 + 절차서** — 버튼 하나로 롤백을 트리거한다. Notion 절차서에 단계·확인 포인트를 적는다.
4. **복구 판단** — 헬스체크 API를 폴링해 A 복구를 확인하고(계획적 롤백), 또는 오류율이 문턱을 넘으면 자동 롤백을 건다(Should).
5. **검증** — 장애 주입 → 60초 안에 A로 100% 복귀(NFR-05), 순번 대조로 누락·중복 0.

## 5. 완료 조건

- 장애 주입 시 **60초 안에 A로 100% 복귀**(NFR-05).
- 역방향 복제 B→A가 동작한다.
- 수동 버튼과 Notion 절차서가 있다(Must). 오류율 자동 롤백은 Should.
- 복귀 후 순번 대조로 누락 0·중복 0.
